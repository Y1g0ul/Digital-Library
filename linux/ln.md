Команда в [[Linux]] для создания ссылок на файлы и каталоги.

```bash
ln [ключи] <источник> <ссылка>
```

|Ключ|Что делает|
|---|---|
|`-s`|создать символическую ссылку|
|`-f`|перезаписать существующую ссылку|
|`-i`|спрашивать перед перезаписью|
|`-v`|подробный вывод|

`ln myfile myfile2` - Создать еще один файл с названием `myfile2` который является хард ссылкой ссылающийся на ту область памяти что и `myfile`. 
`ln -s myfile myfile3` - Создаем еще один файл с названием `myfile3` который уже является просто символичской ссылкой которая указывает на `myfile`

Хард линк это просто имя файла в нашей файловой системе. 
Файл существует пока есть хотя-бы один хард линк
`drwxr-xr-x 2 y1g0ul y1g0ul 4096 Dec  9 10:04 dir`
цифра `2` после прав это как раз и есть количество имен файлов

Жёсткие ссылки (`myfile` и `myfile2`):
   - Это два имени для одних и тех же данных.
   - Если изменить содержимое `myfile`, оно изменится и в `myfile2`.
   - Удаление одного файла не удалит данные, пока есть другая ссылка.
Создаётся только на файлы и в пределах одного диска
Нельзя создавать на файлы в разных дисках ведь у каждого диска уникальные [[inode]]. Нельзя создавать на каталоги.

Символическая ссылка (`myfile3`):
   - Это просто «ярлык». Если удалить `myfile`, ссылка `myfile3` станет «битой» (не будет работать).
   - Права доступа для `myfile3` не имеют значения — они наследуются от `myfile`.
Может создаваться на каталоги в разных дисках. Символическая ссылка содержит в себе **относительный** пута до файла на которые она указывает, а не **абсолютный**. Так что при переносе их в другую директорию они сломаются так же как и при переименовании файла. Так же при их создании лучше указывать полный путь до файла, потому что если мы будем делать ссылку на файл команда будет запускаться в самой папке, где файла естественно не будет. Символическая ссылка (symlink) до 60 байт использует **быстрый (fast) режим**, при котором путь целевого файла хранится прямо в структурах [[inode]] файловой системы (например, ext4), без выделения отдельного дискового блока. Ссылки длиннее 60 байт работают в **обычном (slow) режиме** и требуют выделения полноценного дискового блока для хранения пути. ЕСли за 40 шагов до реального файла не добрались, тогда ядро вернет ошибку.
``` bash
y1g0ul@y1g0ul-PC:~/testdir$ ll
итого 16
drwxrwxr-x  3 y1g0ul y1g0ul 4096 апр  8 10:04 ./
drwxr-x--- 28 y1g0ul y1g0ul 4096 апр  7 09:53 ../
-rw-rw-r--  1 y1g0ul y1g0ul  230 апр  8 10:05 file
drwxrwxr-x  2 y1g0ul y1g0ul 4096 апр  8 10:08 folser/
y1g0ul@y1g0ul-PC:~/testdir$ ln -s file folser/
y1g0ul@y1g0ul-PC:~/testdir$ cat folser/file 
cat: folser/file: Слишком много уровней символьных ссылок
```
Как мы видим в этом примере ссылка получилась битой.

Точка и две точки единственные хард линки на каталоги. `.` - на себя. `..` - на вышестоящий каталог

```bash
ln file.txt hardlink.txt
# создать жёсткую ссылку

ln -s file.txt link.txt
# создать символическую ссылку

ln -s /var/log/nginx ~/nginx-logs
# создать ссылку на каталог

ln -sf new.conf current.conf
# заменить существующую символическую ссылку

ls -l
# посмотреть, куда ведёт символическая ссылка

readlink link.txt
# показать путь, на который указывает ссылка

readlink -f link.txt
# показать полный конечный путь
```
