Logical Volume Manager - это слой абстракции над дисками в [[Linux]], который позволяет объединять несколько физических дисков в единое пространство и гибко управлять разделами без переразметки диска.

![[Excalidraw/LVM]]

---

## PV (Physical Volume / Физический том)    

Первый слой LVM. Обычный диск или раздел, подготовленный для использования в LVM.
```text
/dev/sdb1
   ↓
pvcreate
   ↓
PV
```

При `pvcreate` на устройство записываются **LVM-метаданные**, после чего LVM может использовать его пространство.

PV делится на небольшие одинаковые блоки - **Physical Extents (PE)**. Обычно размер PE - несколько MiB.
```text
PV
├── PE
├── PE
├── PE
└── PE
```

|Команда|Что делает|
|---|---|
|`pvcreate /dev/sdb1`|Делает диск/раздел физическим томом LVM|
|`pvs`|Краткий список всех PV|
|`pvdisplay`|Подробная информация о PV|
|`pvremove /dev/sdb1`|Убирает LVM-метаданные с диска|
|`pvscan`|Сканирует систему на наличие PV|

## VG (Volume Group / Группа томов)

Объединяет один или несколько PV в единый пул свободного пространства, из которого затем создаются логические тома.
```text
PV /dev/sdb1 ─┐
              ├── VG
PV /dev/sdc1 ─┘
```

Для LVM неважно, на каком конкретно диске находится свободное место - VG представляет всё пространство как один общий пул.
```text
VG
├── занято LV
├── занято LV
└── FREE
```

Именно поэтому можно добавить новый диск в существующую VG и затем увеличить уже существующий LV.

|Команда|Что делает|
|---|---|
|`vgcreate vg_name /dev/sdb1`|Создаёт VG из PV|
|`vgs`|Краткий список VG|
|`vgdisplay`|Подробная информация о VG|
|`vgextend vg_name /dev/sdc1`|Добавляет PV в VG|
|`vgreduce vg_name /dev/sdb1`|Убирает PV из VG|
|`vgremove vg_name`|Удаляет VG|

---

- **`LV (Logical Volume / Логический том)`**
    

Виртуальный раздел, который создаётся внутри VG. Для операционной системы выглядит как обычное блочное устройство.

Например:

```text
/dev/vg_name/lv_name
```

LV состоит из **Logical Extents (LE)**, которые LVM связывает с Physical Extents на реальных дисках.

```text
LV:
LE1 LE2 LE3 LE4

 ↓   ↓   ↓   ↓

PV:
PE8 PE9 PE2 PE3
```

LV может физически находиться сразу на нескольких дисках, но для системы он выглядит как одно устройство.

|Команда|Что делает|
|---|---|
|`lvcreate -L 10G -n lv_name vg_name`|Создаёт LV фиксированного размера|
|`lvcreate -l 100%FREE -n lv_name vg_name`|Использует всё свободное место VG|
|`lvs`|Краткий список LV|
|`lvdisplay`|Подробная информация о LV|
|`lvremove /dev/vg/lv`|Удаляет LV|
|`lvresize -L +5G /dev/vg/lv`|Увеличивает LV|
|`lvresize -L 10G /dev/vg/lv`|Устанавливает точный размер|
|`lvresize -r ...`|Меняет LV и файловую систему|
|`lvreduce -L 5G /dev/vg/lv`|Уменьшает LV ⚠️ риск|

---

- **`FS (ext4 / xfs / swap)`**
    

Файловая система создаётся поверх LV и уже отвечает за хранение файлов и каталогов.

```text
LV
 ↓
mkfs.ext4
 ↓
ext4
 ↓
mount
 ↓
/data
```

Важно:

**LV и файловая система — это разные уровни.**

Если увеличить LV:

```bash
lvresize -L +10G /dev/vg/lv
```

то само блочное устройство станет больше, но файловая система внутри может остаться прежнего размера.

Для `ext4`:

```bash
resize2fs /dev/vg/lv
```

Или сразу:

```bash
lvresize -r -L +10G /dev/vg/lv
```

`-r` автоматически изменяет и LV, и файловую систему.

## Как LVM работает под капотом

Основной механизм LVM в ядре Linux — **Device Mapper**.

Он создаёт виртуальное блочное устройство и хранит таблицу соответствия:

```text
логический блок LV
        ↓
Device Mapper
        ↓
физический блок диска
```

Поэтому:

```text
/dev/vg0/data
```

может реально состоять из блоков:

```text
/dev/sdb1
/dev/sdc1
/dev/sdd1
```

Для приложений это всё равно выглядит как один обычный диск.

Посмотреть Device Mapper:

```bash
ls -l /dev/mapper/
```

Например:

```text
/dev/mapper/vg0-data
```

обычно соответствует:

```text
/dev/vg0/data
```

## Расширение LVM

Один из главных плюсов LVM.

Допустим:

```text
/dev/sdb1 → VG → LV 100G
```

Места не хватает.

Добавляем новый диск:

```bash
pvcreate /dev/sdc1
vgextend vg_name /dev/sdc1
lvresize -r -L +50G /dev/vg_name/lv_name
```

Получается:

```text
/dev/sdb1 ─┐
           ├── VG → LV 150G
/dev/sdc1 ─┘
```

При этом не нужно создавать новый отдельный раздел и переносить туда данные.

## Перемещение данных между дисками

Перед удалением PV из VG данные с него нужно перенести:

```bash
pvmove /dev/sdb1
```

LVM перенесёт extents на другие PV внутри этой же VG.

После этого:

```bash
vgreduce vg_name /dev/sdb1
```

и затем:

```bash
pvremove /dev/sdb1
```

## Snapshot

LVM умеет создавать snapshot — состояние LV на определённый момент времени.

```bash
lvcreate -L 5G -s -n snapshot /dev/vg/lv
```

Snapshot не копирует весь диск сразу.

При изменении данных LVM сохраняет старые блоки отдельно — механизм **Copy-on-Write**.

Используется для:

- резервного копирования;
    
- временного сохранения состояния;
    
- отката изменений.
    

Snapshot не является полноценным backup, потому что обычно находится на тех же физических дисках.

## Главная идея для собеседования

```text
PV
→ физический диск, подготовленный для LVM

VG
→ общий пул пространства из нескольких PV

LV
→ виртуальный раздел, созданный из пространства VG

FS
→ файловая система поверх LV

Device Mapper
→ механизм ядра, который связывает логические блоки LV
  с физическими блоками реальных дисков
```

Главное преимущество LVM — возможность изменять размеры томов, добавлять новые диски и перераспределять пространство без классической переразметки дисков.
