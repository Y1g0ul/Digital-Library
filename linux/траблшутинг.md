## Цель 1: Охарактеризовать сервер.

Выясните, чем занимается сервер; каково его назначение (например, веб-сервер, сервер баз данных, сервер обработки данных и т. д.).
``` bash
sudo netstat -tlpn  # becoming obsolete
sudo ss -tlpn  # more modern (same flags!)
```
Конечно, мы можем использовать этот метод [[ps]] и для перечисления всех процессов:
``` bash
sudo ps auxf  # lots of flag options, play with them
```


## Цель 2: Определить уровень использования серверного оборудования.

Определите степень загрузки оборудования (процессора, оперативной памяти, диска, сети) и выявите, есть ли проблемы с какими-либо из этих ресурсов.

Мы можем использовать  [[top]] (или более удобную программу [[htop]], если она установлена) для определения текущей загрузки памяти и процессора .

Тут у нас 2 варината:
1. У нас закончился какой-то ресурс, и надо понять какой
2. Ресурсы свободны, но сервер все равно работает медленно и это значит, что он ждет какой-то внешний сервис.

### Ветка 1: Кончились ресурсы

#### Проверка процессора

Посмотрим вывод команды [[top]]/[[htop]]. Посмотрим колнку procs в [[vmstat]] что бы понять сколько задач ожидают своей доли.
``` bash
vmstat 2 3 # 3 раза с интервалом 2 секунды
```

Посмотрим загрузку по каждому логическому ядру. ([[mpstat]])
``` bash
mpstat -P ALL
```

#### Проверка памяти

Проверим память командой [[free]].
``` bash
free -h
```

Так же что в [[vmstat]], что в [[top]] мы могли увидеть нехватку оперативной памяти и использование [[swap]], в таком случае мы можем проверить не сделал ли ничего [[oom killer]]
``` bash
dmesg | grep -i oom
journalctl -k | grep -i oom
journalctl -k | grep -i "killed process"
```


#### Диск

Мы можем посмотреть статистику дисков через [[iostat]] и какие процессы используют диск в реальном времени через [[iotop]]. Проверить командой [[df]] свободное место и айноды. 
``` bash
df -h # Своодное место
df -i # Айноды
iostat -xz 5 # Статистика диска
iotop -o # Использование диска в реальном времени 
```
