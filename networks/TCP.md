Tранспортный протокол, обеспечивающий надёжную передачу данных между двумя устройствами. Гарантирует, что данные:
- будут доставлены;
- придут в правильном порядке;
- не будут потеряны незаметно;
- не будут продублированы.

Заголовок
1. Номер порта отправителя
2. Номер порта получателя
3. Порядковый номер ( поступающий с прикладного уровня поток байт нумеруется и только потом разбивается на сегменты. Первый номер байта в передаваемом сегменте указывается в порядковый номер )
4. Номер подтверждения ( указывается номер следующего ожидаемого байта, при этом после отправки сегмента запускается специальный таймер ожидания. Если подтверждение о получении сегмента не пришло, то это означает что либо сегмент не был доставлен, либо был доставлен но подтверждение не пришло )
5. Размер окна ( у получателя есть определенный буфер  в который он принимает наши данные и есле он переполнится, то все остальные сегменты будут отброшены. )
6. Контрольная сумма ( [[хеш]] заголовка и данных для проверки корректности, на стороне получателя эта сумма вычисляется снова и еси она не совпадает с той что пришла в заголовке, то сегмент просто отбрасывается)
7. Флаги
	1. ACK - ставится при получении сегмента получателем. Если он у казан в ответе, то для отправителя это значит что в поле с номером подверждения есть информация которую нужно прочитать, в противном случае это поле будет проигнарировано
	2. SYN - используется для установки соединения.
		- Перед тем как начнется передача сегментов, согласно протоколу TCP, должно быть установлено дополнительное соединение. Для этого отправитель посылает TCP сообщение с флагом SYN в котором передает случайный порядковый номер байа, сгенерированный случайным образом. 
		- В ответ получаель отправляет подтверждение с флагами SYN и ACK, передавая свой порядковый номер байта который он сгенерировал и мер подтверждения полученного байта. 
		- В конце отправитель посылает еще одно сообщение с флаом ACK указывая порядковый номер байта который ожидает получатель и подтверждение полученного от него байта. После этого обе стороны готовы к передаче и получению данных друг от друга.
	После того как все данные будут переданы соединение нужно разорвать, для этого используют 2 флага:
	3. FIN - означает что у передающей стороны больше нет данных для передачи, поэтому она хочет соединение разорвать. В ответ на такой сегмент приходит подтверждение с флагм ASK и передающая сторона больше не может отправлять данные. Принимающая сторона точно так же должна отправить сегмент с флагом FIN и получить подтверждение с флагом ASK. После этого соединение считается полностью разорванным в обе стороны.  
	4. RST - разрыв с таким флагом осущетвляется в случае какой-то критической ошибки. В случае получения такого сегмента, соединения закрывается сразу в обе стороны. 
	Следующие 3 флага сигнализируют о перегрузке сети. Сигнализировать об этом может не только потеря пакетов. Если время движения от отправителя до получателя и обратно сильно растет, то это тоже может сигнализировать о загруженности сети, но не всегда. 
	5. ECE - Если маршрутизатор получив пакет понимает, что находитс в состоянии близкому к перегрузке, он заменяет IP заголовок устанавливая специальный флаг. Когда этот пакет дойдет по получателя и он увидит этот флаг, то в подтверждающем сегменте он сообщит отправителя о перегрузке сети поставив флаг ECE.
	6. CWR - В ответ отправитель тоже посылает подтверждение о получении сигнала перегрузки выставля флаг CWR. 
	7. NC - испольуется для защиты от случайного изменения этих флагов.
	На стороне отправителя заводистя специальное окно перегрузки, по которому мы будем определять количество передаваемых сегментов. После каждого получения поджтверждений размер окна будет увеличиваться на 2 сегмента.  
	8. PSH - предназначается для передачи данных программе без промежуточнй записи в буффер
	9. UGR - означает что в сегменте содержатся срочные данные которые необходимо быстро приложению передать. 
8. Указатель на срочныее данные - смещение от порядкового номера байта, до байта которым заканчиваются срочные данные  указываются в соответственном поле заголовка. 
9. Длина заголовка - помогает понять где заканчивается TCP заголовок и где начинаются данные. 

**`Установка TCP-соединения`** происходит в три этапа:
10. `SYN`
	Клиент говорит *Хочу установить соединение*
11. `SYN-ACK`
	Сервер отвечает *Готов принять соединение*
12. `ACK`
	Клиент подтверждает *Отлично, начинаем работу*

**`Передача данных`**
TCP разбивает данные на сегменты.
``` bash
Большой файл
        ↓
TCP Segment 1
TCP Segment 2
TCP Segment 3
...
```
Каждый сегмент получает номер. Благодаря этому получатель может собрать данные обратно в правильном порядке.

**`Повторная передача`**
Это базовая функция протоколов транспортного уровня механизм, при котором сетевой узел (отправитель) автоматически отправляет потерянный или не подтвержденный получателем пакет данных заново. Например `Segment #3` потерялся по дороге. TCP замечает отсутствие ACK и отправляет его снова.

Transmission Control Protocol - транспортный протокол, обеспечивающий **надёжную передачу потока байтов** между двумя устройствами.

TCP обеспечивает:
- контроль доставки данных;
- правильный порядок данных;
- обнаружение потерь;
- повторную передачу потерянных данных;
- обнаружение дубликатов;
- управление потоком;
- управление перегрузкой сети.

При этом TCP не может гарантировать, что данные обязательно будут доставлены: если связь полностью пропала, соединение в итоге завершится ошибкой.

## TCP-заголовок

Основные поля TCP-заголовка:
1. **Source Port** - порт отправителя.
2. **Destination Port** - порт получателя.
3. **Sequence Number** - порядковый номер первого байта данных в данном сегменте.
4. **Acknowledgment Number** - номер следующего байта, который получатель ожидает получить.
5. **Window Size** - сообщает, сколько данных получатель сейчас способен принять.
6. **Checksum** - контрольная сумма заголовка и данных для обнаружения повреждения сегмента.
7. **Flags** - управляющие флаги TCP.
8. **Urgent Pointer** - используется вместе с `URG` для указания срочных данных.
9. **Data Offset** - размер TCP-заголовка, позволяющий определить, где начинаются данные.

## Sequence Number

TCP рассматривает данные как **непрерывный поток байтов**.

Например:
```text
Поток данных:

байт 1000
байт 1001
байт 1002
...
```

После этого поток передаётся TCP-сегментами.

Например:
```text
Segment 1:
SEQ = 1000
данные: байты 1000-1499

Segment 2:
SEQ = 1500
данные: байты 1500-1999
```

Таким образом, `Sequence Number` указывает номер **первого байта данных в сегменте**.

Благодаря этим номерам TCP может:
- восстановить правильный порядок данных;
- определить потерянные данные;
- обнаружить повторно пришедшие данные.

## Acknowledgment Number

Получатель подтверждает получение данных с помощью `ACK`.

Например, он получил:
```text
байты 1000-1499
```

и отвечает:
```text
ACK = 1500
```

Это означает:
```text
Все байты до 1499 получены.
Следующим ожидаю байт 1500.
```

То есть TCP обычно подтверждает не отдельный сегмент, а **полученный диапазон байтов**.

Если подтверждение не приходит вовремя, TCP может повторно передать данные.

## Window Size

У получателя есть буфер для входящих данных.

Он сообщает отправителю, сколько данных способен принять:
```text
Window Size
```

Например:
```text
ACK = 5000
Window = 30000
```

означает примерно:
```text
Следующий ожидаемый байт: 5000
Могу принять ещё 30000 байт
```

Этот механизм называется:
```text
Flow Control
```

Он предотвращает ситуацию, когда быстрый отправитель перегружает медленного получателя.

## Checksum

`Checksum` - контрольная сумма, используемая для обнаружения повреждения данных.

Отправитель вычисляет её перед отправкой, а получатель вычисляет заново.

Если значения не совпадают:
```text
сегмент повреждён
↓
сегмент отбрасывается
```

Checksum - это **не криптографический хеш** и не предназначена для защиты от намеренного изменения данных.

## TCP Flags

### SYN

`SYN` используется для установки TCP-соединения и синхронизации начальных sequence number.

Установка соединения выполняется через `Three-Way Handshake`.

```text
Client                       Server

SYN
SEQ = 100
---------------------------->

              SYN + ACK
              SEQ = 500
              ACK = 101
<----------------------------

ACK
SEQ = 101
ACK = 501
---------------------------->
```

После этого соединение установлено.

То есть:
```text
SYN
↓
SYN-ACK
↓
ACK
```

### ACK

`ACK` означает, что поле `Acknowledgment Number` содержит действительное значение.

Например:
```text
ACK = 1500
```

означает:
```text
Следующим ожидаю байт 1500.
```

Большинство сегментов после установки TCP-соединения имеют установленный флаг `ACK`.

### FIN

`FIN` означает:
```text
У меня больше нет данных для отправки.
```

TCP-соединение является двунаправленным, поэтому каждая сторона закрывает своё направление отдельно.

Обычно закрытие выглядит примерно так:

```text
Client                       Server

FIN
---------------------------->

              ACK
<----------------------------

              FIN
<----------------------------

ACK
---------------------------->
```

После обмена `FIN` и `ACK` соединение полностью закрывается.

### RST

`RST` (`Reset`) используется для немедленного сброса соединения.

Например:
- соединение пришло на закрытый порт;
- произошла серьёзная ошибка;
- приложение принудительно разорвало соединение.

В отличие от `FIN`, это аварийное закрытие без нормального завершения обмена.

### PSH

`PSH` (`Push`) сообщает получателю, что данные желательно как можно скорее передать приложению, не ожидая накопления дополнительного потока данных.

Это не означает полного обхода всех буферов TCP.

### URG

`URG` означает, что поле:

```text
Urgent Pointer
```

имеет значение и указывает на срочную часть потока данных.

На практике этот механизм используется редко.

## ECN

TCP также может использовать `ECN` (`Explicit Congestion Notification`) для обнаружения перегрузки сети **без обязательной потери пакетов**.

Для этого используются флаги:
- `ECE` - получатель сообщает отправителю о признаках перегрузки;
- `CWR` - отправитель сообщает, что отреагировал на сигнал перегрузки;
- `NS` - дополнительный ECN-флаг, практически редко встречающийся.

Маршрутизатор при поддержке ECN может пометить IP-пакет вместо его отбрасывания.

```text
Router обнаружил перегрузку
        ↓
пометил IP-пакет
        ↓
Receiver увидел отметку
        ↓
TCP ECE
        ↓
Sender уменьшает скорость передачи
```

## Передача данных

После установки соединения приложение передаёт TCP поток байтов:
```text
Приложение
     ↓
TCP byte stream
     ↓
TCP segments
     ↓
IP packets
```

Например:
```text
Большой файл
        ↓
Segment 1
Segment 2
Segment 3
...
```

TCP использует sequence number и acknowledgments для восстановления правильного порядка данных.

## Повторная передача

Если данные были потеряны, TCP может отправить их повторно.

Например:
```text
Segment 1 → доставлен
Segment 2 → доставлен
Segment 3 → потерян
Segment 4 → доставлен
```

Получатель продолжает сообщать, что ожидает данные начиная с Segment 3.

Отправитель понимает, что часть данных отсутствует, и выполняет:
```text
Retransmission
```

Повторная передача может происходить, например:
- после истечения таймера `RTO`;
- после нескольких повторяющихся ACK;
- с использованием механизма `SACK`.

## Flow Control и Congestion Control

Это два разных механизма.

### Flow Control

Защищает **получателя**:
```text
Sender слишком быстрый
        ↓
Receiver Window
        ↓
Sender уменьшает объём данных
```

Основной параметр:
```text
rwnd — receive window
```

### Congestion Control

Защищает **сеть от перегрузки**.

Отправитель поддерживает своё окно:
```text
cwnd — congestion window
```

TCP изменяет его размер в зависимости от состояния сети.

Упрощённо:
```text
сеть работает хорошо
        ↓
cwnd увеличивается

потери / признаки перегрузки
        ↓
cwnd уменьшается
```

Реальные алгоритмы могут быть разными, например:

```text
CUBIC
BBR
Reno
```

Поэтому неверно считать, что TCP всегда увеличивает окно ровно на два сегмента после каждого ACK.

## Кратко

```text
TCP
 │
 ├─ порты → определяют приложения
 ├─ SEQ → нумерация байтов
 ├─ ACK → подтверждение данных
 ├─ Window → управление потоком
 ├─ Checksum → обнаружение повреждений
 ├─ Retransmission → повторная передача
 ├─ SYN → установка соединения
 ├─ FIN → нормальное закрытие
 └─ RST → аварийный сброс
```

Главная идея TCP:

```text
Приложение видит надёжный упорядоченный поток байтов,
а TCP самостоятельно занимается сегментацией,
подтверждениями, потерями и повторной передачей.
```
