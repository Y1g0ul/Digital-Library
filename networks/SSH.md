SSH (Secure Shell) - сетевой протокол для безопасного удалённого подключения к другому компьютеру. SSH работает поверх [[TCP]]. Стандартный [[ports]] `22`.

Через SSH можно:
- удалённо войти на сервер;
- выполнять команды;
- копировать файлы;
- делать туннели;
- использовать Git по SSH;
- автоматизировать деплой.


## Как работает SSH

Упрощённо:

```text
SSH-клиент
    ↓
TCP-соединение на порт 22
    ↓
SSH-сервер
    ↓
Проверка подлинности сервера
    ↓
Аутентификация пользователя
    ↓
Зашифрованная SSH-сессия
```

В Linux SSH-сервер обычно реализуется через:

```text
OpenSSH
```

## Клиент и сервер

### SSH-клиент

Команда:

```bash
ssh
```

Используется на устройстве, с которого подключаемся.

Пример:

```bash
ssh nikita@server.example.com
```

### SSH-сервер

Обычно это:

```text
sshd
```

Именно `sshd` слушает входящие подключения.

Проверить:

```bash
systemctl status ssh
```

или в некоторых системах:

```bash
systemctl status sshd
```

---

## Подключение

Формат:

```bash
ssh user@host
```

Пример:

```bash
ssh root@192.168.1.10
```

Если порт нестандартный:

```bash
ssh -p 2222 user@192.168.1.10
```

---

## Аутентификация

Есть два основных способа.

### По паролю

```text
Клиент
↓
Логин + пароль
↓
Сервер проверяет данные
```

Просто, но для серверов обычно менее предпочтительно.

### По SSH-ключу

Используется пара ключей:

```text
Private Key
Public Key
```

Закрытый ключ остаётся у клиента.

Открытый ключ хранится на сервере.

Обычно в:

```bash
~/.ssh/authorized_keys
```

---

## Создание SSH-ключа

Современный вариант:

```bash
ssh-keygen -t ed25519
```

После этого обычно появляются:

```text
~/.ssh/id_ed25519
~/.ssh/id_ed25519.pub
```

Где:

```text
id_ed25519
```

— приватный ключ.

```text
id_ed25519.pub
```

— публичный ключ.

Приватный ключ никому не передаётся.

---

## Копирование ключа на сервер

```bash
ssh-copy-id user@server
```

После этого можно подключаться без ввода пароля пользователя, если сервер разрешает вход по ключам.

## known_hosts

При первом подключении SSH показывает fingerprint сервера.

После подтверждения ключ сервера сохраняется в:

```bash
~/.ssh/known_hosts
```

Это позволяет клиенту проверить, что при следующем подключении он попал на тот же сервер.

Если ключ сервера неожиданно изменился, SSH может показать:

```text
REMOTE HOST IDENTIFICATION HAS CHANGED!
```

Это может означать:

- сервер переустановили;
    
- SSH host key изменился;
    
- IP теперь принадлежит другому серверу;
    
- возможна атака MITM.
