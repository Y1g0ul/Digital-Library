# План подготовки к первой работе

Цель: быть готовым к стажировке / Junior Linux или Junior DevOps. Не нужно выучить всё до откликов: откликаться можно уже сейчас, а этот план проходить параллельно.

## Как пользоваться

- Повторять не определения, а сценарии: **симптом → сбор фактов → причина → безопасное исправление → проверка**.
- После каждой темы сделать хотя бы одну маленькую лабораторную поломку и записать решение в [[траблшутинг]].
- Не пытаться закрыть весь список за раз: сначала приоритет 1, затем один проект, затем приоритет 2.

## Приоритет 1 — обязательно для первой работы

### Linux: эксплуатация и диагностика

Нужно уверенно уметь отвечать: «сервис не работает — что проверишь и что сделаешь?»

- [ ] Найти процесс, его PID, потребление CPU/RAM и открытые порты: [[linux/ps|ps]], [[linux/top|top]], [[linux/free|free]], [[linux/df|df]], [[linux/ss|ss]], [[linux/lsof|lsof]].
- [ ] Диагностировать и перезапустить сервис: [[linux/systemctl|systemctl]], [[linux/systemd|systemd]], [[linux/unit|unit]], [[linux/target|target]].
- [ ] Читать и фильтровать логи, понимать порядок событий: [[linux/journalctl|journalctl]], [[linux/логи|логи]], [[linux/rsyslog|rsyslog]], [[linux/logrotate|logrotate]].
- [ ] Понимать причины нехватки ресурсов: [[linux/load average|load average]], [[linux/iostat|iostat]], [[linux/vmstat|vmstat]], [[linux/oom killer|OOM killer]], [[linux/cgroups|cgroups]], [[linux/ulimit|ulimit]].
- [ ] Работать с дисками и восстановлением: [[linux/df|df]], [[linux/du|du]], [[linux/blkid|blkid]], [[linux/findmnt|findmnt]], [[linux/mount|mount]], [[linux/fstab|fstab]], [[linux/LVM|LVM]], [[linux/fsck|fsck]], [[linux/rsync|rsync]].
- [ ] Понимать пользователей, группы и права: [[linux/Пользователи|пользователи]], [[linux/права|права]], [[linux/sudo|sudo]], [[linux/SUID|SUID]], [[linux/SGID|SGID]], [[linux/Sticky Bit|Sticky Bit]].
- [ ] Писать короткий Bash-скрипт с аргументами, условиями, циклами, кодами возврата и логированием: [[bash/bash|Bash]], [[bash/Аргументы|аргументы]], [[bash/Условная конструкция if..then..else|if]], [[bash/Цикл for|for]], [[linux/код возварата|коды возврата]], [[linux/logger|logger]].

### Сети: закрыть минимум, нужный для диагностики

Не заучивать все протоколы подряд. Важнее уметь локализовать: DNS, маршрут, firewall или само приложение.

- [ ] Адресация, подсети, шлюз и маршрутизация: [[networks/IP|IP]], [[networks/Маска подсети|маска подсети]], [[linux/ip|ip]], [[linux/netplan|netplan]].
- [ ] DNS: запись, резолвинг, `dig`, различие A/AAAA/CNAME, типовые причины «домен не открывается»: [[networks/DNS|DNS]], [[linux/dig|dig]], [[linux/getent|getent]].
- [ ] TCP/UDP и порты: handshake, состояния соединений, `listen`/`established`, разница TCP и UDP: [[networks/TCP|TCP]], [[networks/UDP|UDP]], [[networks/ports|порты]], [[linux/ss|ss]], [[linux/nc|nc]].
- [ ] Путь пакета и захват трафика: [[networks/Модель OSI|модель OSI]], [[networks/NAT|NAT]], [[linux/ping|ping]], [[linux/traceroute|traceroute]], [[linux/mtr|mtr]], [[linux/tcpdump|tcpdump]].
- [ ] Firewall: входящий, исходящий и транзитный трафик; правила по умолчанию; **сохранение и восстановление правил**: [[linux/nftables|nftables]], [[linux/iptables|iptables]].

### Git, Docker и CI/CD

- [ ] Рабочий Git-поток: ветка → коммиты → pull request → review → merge; уметь разрешить конфликт и отменить неудачное изменение: [[git/branch|branch]], [[git/merge|merge]], [[git/rebase|rebase]], [[git/restore|restore]], [[git/revert|revert]], [[git/reset|reset]].
- [ ] Самостоятельно собрать небольшой сервис: Dockerfile, слои, `.dockerignore`, переменные, ports, volumes, networks, healthcheck: [[docker/docker build|docker build]], [[docker/docker run|docker run]], [[docker/docker compose|Docker Compose]], [[docker/docker network|Docker network]], [[docker/docker volume|Docker volume]], [[docker/docker logs|Docker logs]].
- [ ] Диагностировать контейнер, который не стартует или недоступен: [[docker/docker ps|docker ps]], [[docker/docker logs|docker logs]], [[docker/docker exec|docker exec]], [[docker/docker container inspect|inspect]].
- [ ] Сделать GitHub Actions workflow: checkout → lint/test → build image; отделять Variables от Secrets и не хранить секреты в Git: [[cicd/Workflow|Workflow]], [[cicd/Job|Job]], [[cicd/Step|Step]], [[cicd/Variable|Variable]], [[cicd/Secrets|Secrets]], [[cicd/Artifact|Artifact]], [[cicd/Cache|Cache]].

## Главная практика — один законченный проект

Сделать и выложить отдельным репозиторием проект «наблюдаемое контейнерное приложение».

- [ ] Flask-приложение + PostgreSQL + Nginx reverse proxy в Docker Compose.
- [ ] `README`: схема архитектуры, быстрый запуск, переменные окружения, команды диагностики и способ отката.
- [ ] `healthcheck`, named volumes, отдельная Docker-сеть, `.env.example`; реальные пароли и токены не коммитить.
- [ ] GitHub Actions: проверка кода/сборка образа на pull request.
- [ ] Намеренно сломать три сценария и записать разбор: приложение не отвечает, БД недоступна, Nginx возвращает 502.
- [ ] Настроить backup БД и один раз восстановить его в чистую среду.

Этот проект важнее новой порции теории: его можно показать в резюме и разбирать на собеседовании.

## Приоритет 2 — следующий шаг: мониторинг

Переходить сюда после базового проекта. Это **не рано**: Prometheus и Grafana естественно продолжают Linux и Docker.

- [ ] Понять, что такое метрика, labels, scrape, exporter и alert: [[roadmap#📊 Prometheus + Grafana|список тем]].
- [ ] Добавить в проект Prometheus, Grafana, node-exporter и cAdvisor.
- [ ] Сделать dashboard: доступность приложения, CPU/RAM, место на диске, использование контейнеров.
- [ ] Написать 2 alert-правила: приложение недоступно; заканчивается место на диске.
- [ ] Отправить alert в тестовый канал (например, Telegram) и проверить, что он приходит и закрывается.

## Приоритет 3 — Kubernetes

Начинать после Docker-проекта с мониторингом. Не надо сразу идти в облака, kubeadm или production-кластеры.

- [ ] Поднять локальный кластер через Minikube или kind.
- [ ] Развернуть своё приложение: Pod, Deployment, Service, ConfigMap, Secret, Ingress.
- [ ] Настроить readiness/liveness probes, requests/limits, rollout и rollback.
- [ ] Понять различие Docker, containerd и Kubernetes.
- [ ] Ориентир по последовательности: [[roadmap#☸ Kubernetes|Kubernetes roadmap]].

- [ ] Terraform: сеть, виртуальная машина и переменные в одном облаке.

## Ритм на неделю

- 2 занятия — повторение Linux и сетей через практические инциденты.
- 2 занятия — основной проект.
- 1 занятие — Git/Docker/GitHub Actions, применённые к проекту.
- После завершения проекта — 2 занятия мониторинга и 1 занятие Kubernetes.
- Раз в неделю — 3–5 откликов на стажировки и Junior-вакансии. Отказы и вопросы с собеседований добавлять в [[траблшутинг]] или отдельные заметки.

## Готовность к откликам

Можно откликаться уже сейчас, если без подсказок способен:

- [ ] Поднять Docker Compose-проект и объяснить его сеть, volumes и переменные.
- [ ] Найти причину падения systemd-сервиса через логи и предложить безопасный фикс.
- [ ] Проверить доступность сервиса с помощью DNS, маршрута, порта, firewall и логов.
- [ ] Сделать branch/PR, разрешить конфликт и откатить неудачный коммит.
- [ ] Честно рассказать, что Kubernetes/Terraform ещё изучаются, и показать свой план и проект.
